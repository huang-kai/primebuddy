# 安装向导与独立技能开发计划

目标：Python 3.10+，框架和技能独立开发；ZIP/Git 共用安装流程；由技能提供配置引导，框架统一呈现；只有就绪技能进入 LLM 目录。

## 平台入口与向导职责整理（0.3.0，2026-10-10）

成功标准：框架不处理业务二维码或加载 Pillow；点歌台自己完成扫码展示和清理；用户只需 `primebuddy start` 启动；开发模拟与正式运行分开；README 能供新开发者理解架构、安装、启动参数和技能契约。

1. 将二维码上下文管理、像素渲染及测试移入点歌台的 `src/qr.py`。QQ 登录只调用技能内函数，以最小 `ui.info` 接口验证成功、过期、超时和取消，保留图片私有权限与清理。点歌台独立版本更新为0.2.3，与新框架一起发布和更新，不保留旧二维码接口。
2. 用户确认统一使用 `start`；合并命令解析，删除 `--voice/--live/--allow-only-voice` 组合和旧别名。`simulate` 始终创建模拟上下文，源码技能目录仅能在模拟入口使用；`start` 只加载已安装就绪技能，保留设备预检、音频锁、接管及退出恢复。没有技能时也允许进入平台会话；支持能力以当前目录为准。
3. 保留两项确有用途的启动覆盖：ROS 兼容桥接和 ASR 对比模型。技能目录查看归入 `skill catalog`，预合成归入 `tts warmup`，不向主命令增加业务参数。新增 CLI 回归覆盖帮助、启动、参数拒绝、计划/文字模拟与缓存预热。
4. README 按开发者入口重写，说明当前仅有 T1 适配的实际边界、目录与契约、ZIP/Git 安装、全部命令、升级顺序及未修复的多轮接话问题；同步 SDK 和点歌台说明。使用真实临时发布包验证安装入口及随包二维码模块。
5. 按用户确认，主向导读取随包清单版本，将较新的技能默认选为更新；调用同一安装器及新技能自己的配置向导，沿用私有数据。相同版本仅重新配置，不降级较新的已安装版本；用户取消勾选则不更新。增加版本比较、取消更新及损坏清单回归。

开发阶段仅修改本地源码与生成发布包，未连接或更新 T1，未调用模型服务、QQ 登录或机器人控制接口。

验证结果：仅含公开提交文件的临时工作区共发现191项测试（框架126、点歌台65），182项通过，9项因未分发厂商 SDK 夹具而明确跳过。覆盖真实临时 ZIP 解压安装、发布包内向导升级技能且保留配置、终端按键恢复、旧参数拒绝、模拟与真实入口分离、二维码取消/超时清理。框架25个与点歌台9个 Python 源文件通过 Python 3.10 语法检查；README 的 JSON/Python 示例与相对文档链接已核对。包内点歌台0.2.3包含自己的二维码模块，框架源码不再引用 Pillow 或 `ui.qr()`。另验证了从 primeskills Git 仓库分别生成点歌台、易来 ZIP 并通过安装器来源校验，以及框架随包点歌台的完整打包。

后续按用户要求，于2026-10-10将框架0.3.0与点歌台0.2.3一起部署到 T1 业务板。实际执行新技能的配置入口，QQ 登录校验有效，沿用每首60秒及已启用的音乐联动；模型和 QQ 凭据文件保持不变。发布包散列、部署源码、命令入口、LLM 技能目录、技能运行/配置模块、Pillow及系统 ROS 语音消息类型检查通过。未启动平台、切换 Agent 模式或执行音频与机器人动作；完整语音和点歌流程待现场试用。

## Qwen Audio TTS Plus 接入（0.2.5，2026-10-10）

2. 先以接口请求、旧配置升级、缓存隔离和失败响应测试复现差异，再修改预设和 TTS 请求。验证 workspace Host、WAV/24kHz、完成状态、下载不携带 Key，以及失败不静默回退旧模型。
3. 运行框架及独立技能回归，检查 Python 3.10 兼容性并制作 ZIP；若 T1 可连接，使用已有凭据进行一次短句云端合成，只校验文件、不播放。上海话和主观音质需另行试听验收。

验证结果：新增7项回归，修改前复现6处失败；完成接入后共186项通过（框架124、点歌台62）。全部25个框架源码文件通过 Python 3.10 语法检查；T1 系统 Python 3.10.12 上11项 TTS/缓存测试通过。真实 Plus 请求使用既有凭据和 `longanlingxin` 合成“连接成功。”，返回1.36秒、65,324字节 WAV，总耗时2.437秒；未播放，不能据单次请求推断音质或总体延迟提升。用户确认继续采用 Plus 普通话，不为上海话增加配置或更换模型。
