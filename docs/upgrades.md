# 更新框架与技能

先按 Ctrl+C 退出正在运行的 PrimeBuddy，等待原厂模式恢复，再在实际安装 Buddy 的板上执行：

```bash
# 只检查最新正式版本和已安装技能的兼容性
primebuddy update --check

# 更新到 GitHub 最新正式 Release，保留兼容的已安装技能，仅对不兼容的托管官方技能安排更新
primebuddy update

# 指定目标版本
primebuddy update --version 1.2.0
```

更新在当前安装板完成，不重新选择板、不启动 Buddy、不切换原厂模式。更新器先检查目标发布清单、现有技能及运行状态，准备全部需要的包和 Python 依赖，验证后统一替换框架与技能代码。配置、登录数据、QQ 设备身份和技能启用状态保持；未安装的技能不会自动安装，技能也不会因更新而自动启用或重新扫码。

每个框架版本的 [release.json](../release.json) 声明官方技能的兼容范围和固定推荐版本。技能仍可独立运行；这份表仅约束它们与 Buddy 的配合，不代表必须安装。1.2.0 的配套版本如下：

| Skill | 兼容范围 | 推荐版本 |
| --- | --- | --- |
| `chengyu-chain` | `>=0.1.0, <0.3.0` | `0.2.0` |
| `diangetai` | `>=0.4.0, <0.5.0` | `0.4.1` |
| `yeelight` | `>=0.3.0, <0.4.0` | `0.3.1` |

更新器读取技能目录中的实际版本，不只依赖安装索引。自定义或外部目录中的技能只检查、提示，不覆盖源码；有冲突时先处理对应技能，再继续升级。手动安装、启用技能和启动框架也使用同一兼容检查。已停用的不兼容技能不阻止启动，重新启用前需要升级。

更新失败时恢复本次更新前的代码和安装记录。若断电或进程中断留下未完成事务，先执行：

```bash
primebuddy update --recover
```

此命令不联网，也不启动服务：未完成的更新回退到更新前的版本；已完成提交但尚未清理记录的更新保留新版本，只完成清理。如果命令入口不可用，使用更新开始前显示的独立恢复命令。恢复完成后再重新检查或更新；不要手动删除事务记录来绕过检查。

**从 1.0.0 首次升级：** 旧版没有 `update` 命令。下载、解压新的 RPK，在原安装板进入解压后的 `primebuddy` 目录，运行 `source ./scripts/install.sh`。安装器会联合更新框架和已安装的官方技能，并保留配置、登录和启用状态；之后即可使用 `primebuddy update`。全新安装仍通过 `onboard` 自行选择要安装的技能。

## 不兼容或损坏的技能

兼容不意味着永久维护所有旧接口。启动发现时，单个技能的元数据、协议、入口、私有 YAML 配置或兼容检查失败，只隔离该技能，不阻止其他有效技能加载。日志和 `primebuddy skill list` 显示隔离原因；能力目录不包含该技能。安装记录路径无效或包已缺失也按技能隔离；同名冲突的技能全部隔离，不任意选择其中一个运行。

处理规则：

1. 隔离表示本次不加载，不修改用户原来的启用选择，不删除代码、配置或登录数据，也不静默更换版本。修复后重启会重新检查；原先手动停用的技能仍保持停用。
2. 已知名称的坏包仍可运行 `primebuddy skill disable <名称>` 停用，未知协议不会影响其他技能的配置。重新启用必须通过元数据、兼容、入口和配置校验。检查原因可用 `primebuddy skill list`；按提示修复配置或更新包后重启。
3. 若技能有运行中的进程或未释放资源，先清理并核验；仅从目录禁用不能代替停止播放器或运动控制。共享资源无法确认安全释放时，相关能力继续隔离。
4. 平台整体配置、发行清单或整个技能索引的 YAML 损坏，仍明确报错，不假装平台配置有效。升级事务采用严格检查：发现无法解析的包时中止升级并保留原安装，不能拿不完整的发现结果提交升级。

默认大包只带点歌台和成语接龙。易来的兼容规则仍保留在清单内；已安装旧易来需要升级时，在线 `update` 可下载其独立包。使用解压包离线升级时，需要另行准备对应独立包，不能把“兼容目录”当作“大包包含全部技能”。
